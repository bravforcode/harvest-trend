## 3. วัตถุประสงค์และฐานการประมวลผล

- **รายงานราคา:** เพื่อแสดงราคาเฉลี่ยให้เกษตรกรคนอื่นเห็น · ฐาน: ความยินยอม (ติ๊กก่อนส่งทุกครั้ง)
- **ซิงก์รายการติดตามและการแจ้งเตือน:** เพื่อให้ฟีเจอร์ที่ผู้ใช้เลือกเปิดทำงาน · ฐาน: ความยินยอมหรือการเปิดใช้งานฟีเจอร์โดยผู้ใช้
- **สถิติการใช้งาน:** ไม่มีข้อมูลส่วนบุคคล จึงไม่ต้องอาศัยฐานความยินยอม

ให้ที่ปรึกษาตรวจว่าเข้าเงื่อนไขมาตรา 19 และมาตรา 24 ของ พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 หรือไม่

## 4. ระยะเวลาเก็บ

12 เดือนนับจากการใช้งานครั้งล่าสุดสำหรับข้อมูลที่ผูกกับบุคคล (`user_id`, `line_sub`, `push_subs`, รายชื่อผู้ติดตาม) · เจ้าของโครงการยืนยันแล้ว · ที่ปรึกษากฎหมายยังต้องตรวจ

รายงานราคาที่เป็นข้อมูลสาธารณะ ควรระบุแยกว่าลบเมื่อใดและลบอย่างไร (ดู §6)

## 5. ผู้ประมวลผลข้อมูลและการโอนข้ามประเทศ

## 6. สิทธิของเจ้าของข้อมูลและการลบ

สิทธิที่ต้องแจ้ง: เข้าถึงข้อมูล · ขอแก้ไข · ขอลบ · ถอนความยินยอม · คัดค้าน · ร้องเรียนต่อ สำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล

**ข้อจำกัดที่ต้องแก้ก่อนเผยแพร่:** ตาราง `price_reports` ไม่มีนโยบายลบหรือแก้ไขสำหรับ client (ตาม `supabase/schema.sql`) การลบต้องทำโดยผู้ดูแลใน Dashboard จึงต้องมี
- ช่องทางรับคำขอ (อีเมลหรือ LINE OA)
- ขั้นตอนลบภายในกี่วันทำการ [ยังไม่ได้กำหนด]

## 7. ประเด็นที่ตรวจพบจากโค้ด (ต้องตัดสินใจก่อนเผยแพร่)

1. **ข้อความยินยอมในแอปไม่ตรงกับการเก็บจริง** — `src/lib/i18n.ts` บรรทัด 477 (ไทย) และ 669 (อังกฤษ) เขียนว่า "ไม่มีการเก็บตำแหน่ง GPS หรือข้อมูลส่วนตัว" แต่หมายเหตุเป็นข้อความอิสระ และ `user_id` อาจถูกบันทึกในกรณี fallback **แก้แล้วใน working tree (ยังไม่ commit) เจ้าของโครงการอนุมัติถ้อยคำนี้แล้ว** ถ้อยคำที่ใช้:
   > ข้าพเจ้ายินยอมให้ข้อมูลรายงาน (จังหวัด พืช ราคา หน่วย และหมายเหตุที่ข้าพเจ้าพิมพ์) เผยแพร่เป็นข้อมูลสาธารณะ และจัดเก็บที่เซิร์ฟเวอร์ในสิงคโปร์ ระบบไม่เก็บตำแหน่ง GPS กรุณาอย่าพิมพ์ข้อมูลที่ระบุตัวบุคคลในหมายเหตุ

2. **`user_id` อ่านได้สาธารณะ** — นโยบาย `select all` ใน `supabase/schema.sql` ให้ `anon` และ `authenticated` อ่านได้ทุกคอลัมน์ รวม `user_id` ผลคือรหัสผู้ใช้แบบ anonymous ถูกเปิดเผยต่อสาธารณะในกรณี fallback ทางเลือก:
   - ตัด fallback ออก (รายงานทุกรายการเป็นนิรนาม) หรือ
   - จำกัดสิทธิ์อ่านคอลัมน์ `user_id` (ต้องแก้ไข query `select('*')` ใน `src/lib/supabase.ts`)
   **แก้แล้วใน working tree:** ไคลเอนต์เลือกคอลัมน์ชัดเจนแล้ว (`src/lib/supabase.ts`) และเพิ่ม migration `supabase/migrations/20261024120000_price_reports_hide_user_id.sql` (ยังไม่ได้รันกับโปรเจกต์จริง) รันแล้วกับ harvest-ecc เมื่อ 2026-10-25 หลังเจ้าของโครงการอนุมัติ ยืนยันแล้วว่า anon อ่านคอลัมน์สาธารณะได้ และอ่าน user_id ไม่ได้ · ปิดสิทธิ์ UPDATE/DELETE/TRUNCATE/REFERENCES/TRIGGER แล้วด้วย migration `20261024182852` (2026-10-25) · INSERT คงไว้เพราะแอปใช้ส่งรายงาน · การ revoke คอลัมน์อย่างเดียวไม่มีผล เพราะสิทธิ์ SELECT ระดับตารางยังครอบคลุมทุกคอลัมน์ migration จึง revoke ทั้งตารางแล้ว grant เฉพาะคอลัมน์สาธารณะ

3. **ยังไม่มีหน้านโยบายในแอป** — ปุ่มยินยอมไม่มีลิงก์ไปยังเอกสารนี้ ต้องเพิ่มหน้าและลิงก์เมื่อนโยบายพร้อม
