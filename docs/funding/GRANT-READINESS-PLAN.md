## 0. สรุปผู้บริหาร

Harvest Trend เป็น PWA ที่ช่วยเกษตรกรไทยตัดสินใจ "เก็บเกี่ยว/ขายตอนไหน" ใน 2 แตะ โครงสร้างหลักใช้งานได้จริง
(ฟรอนต์เอนด์ · API ราคาจาก ธปท. · LINE OA bot · Web Push · Supabase sync · เทส 449 รายการ)

**แต่ยังไม่พร้อมยื่นขอทุน** เพราะมีช่องว่างสามกลุ่มที่ผู้ประเมินทุนจะจับได้ทันที:

1. **ความซื่อสัตย์ของข้อมูล (ต้องแก้ก่อนทุกอย่าง)**
   - สัญญาณ "สภาพอากาศ 15%" ไม่ได้มาจากข้อมูลอากาศจริง แต่มาจากฟังก์ชันสุ่มที่ seed ด้วยชื่อจังหวัด+พืช
     (`src/lib/engine.ts:137-138`, `rng01('wx:' + province + ':' + crop)`) ขณะที่ README บอกว่าเป็น "ข้อมูลสภาพอากาศรายจังหวัด" (README.md ตาราง Verdict Engine)
   - ราคาจริงมี source ที่เชื่อมไว้ 26 รายการใน `api/prices.js` ครอบคลุม 17 พืช จาก 25 พืช · วัดแล้วใน `docs/funding/coverage-table.md`: จาก 77 จังหวัด × 25 พืช (= 1,925 คู่) มีข้อมูลระดับจังหวัดจริง 18 คู่ และข้อมูลระดับประเทศ 535 คู่ (รวม 553 คู่ที่มีข้อมูล) · 1,372 คู่ไม่มีข้อมูล
     ส่วนที่เหลือเป็นข้อมูลจำลอง ซึ่งติดป้ายไว้แล้ว แต่ต้องรายงานสัดส่วนนี้ให้ชัดในข้อเสนอ
2. **ความน่าเชื่อถือเชิงวิศวกรรม**
   - README มี badge "tests" แต่ CI ยังไม่เคยรันบน GitHub: มี workflow `.github/workflows/ci.yml` (commit `84df770`) รอ push เพื่อยืนยันผล
   - ตัวเลขเทสเคยไม่ตรงกันข้ามเอกสาร (README 421, PRODUCT.md 51) แก้แล้วเป็น 449 ทั้งสองไฟล์ (commit `9a65028`) และมี guard ใน `tests/docs-claims.test.js`
3. **เอกสารเชิงสถาบันที่ผู้ให้ทุนต้องการ**
   - ไม่มีไลเซนส์ (README ระบุ "ยังไม่ได้กำหนด") · ไม่มีนโยบายความเป็นส่วนตัว/PDPA ฉบับเต็มแยกไฟล์ (มีการขอความยินยอมใน `ReportPage.tsx` แต่ยังไม่มีเอกสาร)
   - ไม่มีโดเมนจริง (ใช้ `harvest-ecc.vercel.app`) · ไม่มีแผน ทีม งบ ตัวชี้วัดผลกระทบ

**คำแนะนำ:** ใช้ 6 สัปดาห์แรกปิดช่องว่างกลุ่ม 1–3 ก่อน แล้วค่อยทำ pilot กับเกษตรกรจริง (WP1–WP4) จากนั้นจึงยื่นทุน
ถ้ายื่นก่อนทำ pilot ผู้ประเมินจะถามเรื่อง "หลักฐานผลกระทบ" ซึ่งตอนนี้ยังไม่มี

## 3. ความสอดคล้องกับการเรียกทุน (Fit)

- **SDG ที่โครงการอ้าง:** 1 (ขจัดความยากจน) · 2 (ขจัดความหิวโหย) · 8 (งานที่มีคุณค่า) · 12 (การบริโภคและการผลิตที่ยั่งยืน)
- **Track ที่ระบุใน README:** "EEC-SDG Hackathon & Pitching 2026 · Track 5 Smart Agriculture & Food Security" — **ยังยืนยันไม่ได้** ว่าเป็นงานใด/ผู้จัดคือใคร (ดูหัวข้อ 4)
- **ประเด็นที่ผู้ให้ทุนจะถาม:**
  1. ทำไมเกษตรกรต้องเปลี่ยนพฤติกรรม (มีราคาอยู่แล้วจากหลายแหล่ง)
  2. ความแตกต่างจากข้อมูลราคาที่มีอยู่ (ราคาจาก กรมการค้าภายใน / ตลาดกลาง / ผู้ค้าในพื้นที่)
  3. หลักฐานว่าคำแนะนำช่วยให้ขายได้ราคาดีขึ้นจริงหรือไม่
  4. ต้นทุนการดูแลข้อมูลระยะยาวใครจ่าย
  5. ข้อมูลส่วนบุคคล: เก็บอะไร ที่ไหน ใครเข้าถึง (รายงานราคาเก็บใน Singapore ตาม README)

**จุดแข็งที่ควรเน้น:** deterministic engine ตรวจสอบได้ · ทำงาน offline · ป้ายแหล่งข้อมูลชัด · ไม่เก็บ GPS · ไม่ขายข้อมูล (ต้องยืนยันก่อนเขียนลงเอกสาร)

## 4. การค้นหาแหล่งทุน (Funding landscape)

> ⚠️ ผลค้นหาในรอบนี้ **ยังไม่ครบ** และ **ยังไม่มีการยืนยันว่าเปิดรับสมัครอยู่** ก่อนยื่นต้องเปิดเว็บหน่วยงานโดยตรง

### 4.1 ไทย (ต้องตรวจเว็บหน่วยงานโดยตรง)

| หน่วยงาน | ความเกี่ยวข้อง | สถานะที่พบ |
|---|---|---|
| **สำนักงานนวัตกรรมแห่งชาติ (NIA)** | ทุนนวัตกรรม/สตาร์ทอัพ · โปรแกรม agri-tech | พบข่าวโปรแกรม agri-tech แต่ข่าวมีอายุหลายปี · ต้องตรวจรอบเปิดรับปี 2026–2027 |
| **depa (สำนักงานส่งเสริมเศรษฐกิจดิจิทัล)** | ทุน/โปรแกรมดิจิทัลเพื่อเกษตร | ไม่พบรอบเปิดรับที่ยืนยันได้ |
| **NSTDA (สวทช.)** | ทุนวิจัยและพัฒนา รวมภาคเกษตร | ไม่พบรอบเปิดรับที่ยืนยันได้ |
| **EEC / สกพอ.** | งานประกวดและทุนในพื้นที่ EEC (ระยอง/ชลบุรี/ฉะเชิงเทรา) | ต้องยืนยันชื่องาน EEC-SDG Hackathon 2026 และผู้จัด |
| **กองทุนสนับสนุนการวิจัย (TRF/NRCT)** | ทุนวิจัยเชิงระบบ/ทุนนักวิจัยรุ่นใหม่ | ต้องมีนักวิจัยหลักที่มีสังกัด |
| **สำนักงานพัฒนาวิทยาศาสตร์และเทคโนโลยีฯ / กรมส่งเสริมการเกษตร (DOAE)** | พันธมิตรข้อมูล/pilot มากกว่าผู้ให้ทุน | เป็นแหล่งร่วมมือที่เหมาะกว่า |

ช่องทางเชิงกลยุทธ์ที่ควรเปิด: กรมการค้าภายใน, ธปท., สำนักงานเศรษฐกิจการเกษตร (OAE) เป็น "พันธมิตรข้อมูล" เพื่อให้ได้ข้อมูลราคาที่ได้รับอนุญาต ซึ่งมีค่ามากกว่าเงินทุนในการยืนยันความน่าเชื่อถือ

### 4.2 ระดับนานาชาติ (ทบทวนแล้วบางส่วน)

| โปรแกรม | สิ่งที่พบ | ความเหมาะกับไทย |
|---|---|---|
| GAFSP (World Bank) | เปิดรับรอบ 2026 ที่ปิดเก็บเอกสาร 15 ก.ย. 2026 · เป้าหมายคือรัฐในประเทศรายได้น้อย | **ไม่เหมาะ** (ผู้สมัครคือรัฐบาล) |
| UNDP (ตัวอย่างเลบานอน) | ทุนขนาดเล็กให้เกษตรกร/กลุ่มเกษตรกร | ใช้เป็นแบบอย่างโครงสร้างเท่านั้น ไม่ตรงพื้นที่ |
| Common Fund for Commodities (CFC) | ทุนสูงสุด ~$750K ต่อโครงการ ให้ agribusiness ใน 101 ประเทศ | **ต้องตรวจว่าไทยอยู่ในรายชื่อ** และกำหนดเวลาปัจจุบัน |
| IFC Agritech Modernization Grant | สมัครได้ถึง 10 ต.ค. 2026 (ปิดแล้ว) · เน้น sub-Saharan Africa และ South Asia | **ไม่เหมาะ** |
| Global Innovation Fund / Google.org / Gates | ค้นหาไม่พบประกาศที่ยืนยันได้ในรอบนี้ | **ต้องตรวจเว็บโดยตรง** |

> สรุป: แหล่งทุนที่เหมาะที่สุดในช่วงแรกคือ **ทุนในประเทศ (NIA/depa/NSTDA/EEC)** และ **หน่วยงานรัฐเป็นพันธมิตรข้อมูล** ส่วนทุนนานาชาติควรทำในรอบถัดไปหลังมีหลักฐาน pilot

### 4.3 ขั้นตอนค้นหาที่ยังต้องทำ (งาน WP0)
1. เปิดเว็บ NIA, depa, NSTDA, EEC/สกพอ., TRF แล้วบันทึกรอบเปิดรับ ปีงบ 2026–2027 พร้อมวันปิด เงินสูงสุด และเงื่อนไขผู้สมัคร
2. ยืนยันชื่อและผู้จัด "EEC-SDG Hackathon & Pitching 2026" จากเอกสารต้นทาง
3. สำรวจ fundsforNGOs / Pertama / Global South Opportunities เฉพาะรอบที่มีไทยในเงื่อนไข
4. บันทึกทุกแหล่งลง `docs/funding/funder-tracker.md` (ชื่อ, ลิงก์, วันปิด, เงิน, เงื่อนไข, สถานะ)

- [ ] **ซื้อโดเมนจริง** และตั้ง canonical/sitemap ให้ตรง
- [ ] **ทำ checklist "ข้อมูลจำลอง"** ทุกหน้า/API แล้วเพิ่มเทสอัตโนมัติว่าทุกเส้นทางติดป้าย
- [ ] **ค้นหาแหล่งทุน** ตามหัวข้อ 4.3

**เกณฑ์ผ่าน:** CI เขียวบน master · ไม่มีคำอ้างที่โค้ดไม่รองรับ · มีไลเซนส์และนโยบาย PDPA · มีโดเมนจริง

### WP1 · ข้อมูลราคาและพันธมิตรข้อมูล (สัปดาห์ 2–12)
- [ ] ทำตารางครอบคลุม: ต่อพืช 25 ชนิด × จังหวัด 77 จังหวัด → จำนวนคู่ที่เป็นข้อมูลจริง / จำลอง (ตัวเลขที่ต้องรายงาน)
- [ ] ขยาย source จริงในพืชที่มีความต้องการสูง เช่น ทุเรียน ยางพารา ข้าว (เริ่มจากพื้นที่ EEC และจันทบุรี/ตราด)
- [ ] จดหมายขอความร่วมมือข้อมูลถึง กรมการค้าภายใน / ตลาดกลาง / OAE / สหกรณ์ (เป็น "letter of support" ในชุดยื่น)
- [ ] ตรวจสอบเงื่อนไขการใช้ข้อมูลของทุก source (BOT, data.go.th, ข่าว) และบันทึกในไฟล์แยก
- [ ] ทำ data dictionary: แหล่ง, ความถี่, หน่วย, วันที่ล่าสุด, วิธีแปลง

### WP2 · การตรวจสอบความถูกต้องของเอนจิน (สัปดาห์ 4–14)
- [ ] **Backtest:** ใช้ข้อมูลราคาจริงย้อนหลังอย่างน้อย 3 ปี คำนวณว่าคำแนะนำ "ขายได้เลย / รอได้ / รีบขาย" ตรงกับทิศทางราคาใน 4 สัปดาห์ถัดไปกี่เปอร์เซ็นต์ (hit rate) และ baseline ที่ง่ายกว่า (เช่น "ขายทันที", "สุ่ม") เทียบกันอย่างไร
- [ ] **Calibration:** ระดับความมั่นใจสัมพันธ์กับความแม่นยำจริงหรือไม่
- [ ] รายงานผลทั้งที่ดีและไม่ดี เพื่อไม่ให้ผู้ตรวจพบภายหลัง
- [ ] เขียนเอกสารวิธีการ (methods note) ให้ผู้เชี่ยวชาญด้านเศรษฐศาสตร์เกษตรตรวจ

**หมายเหตุ:** คำแนะนำนี้ไม่ใช่คำแนะนำทางการเงิน (README ระบุแล้ว) แต่ผู้ให้ทุนจะต้องการเห็นว่า "แม่นกว่าการเดาพอสมควร"

### WP3 · Pilot กับเกษตรกรจริง (สัปดาห์ 8–24)
- [ ] เลือกพื้นที่นำร่อง 2 จังหวัด (แนะนำ: จันทบุรี/ตราด สำหรับทุเรียน และ 1 พื้นที่สำหรับพืชไร่ เช่น ข้าวโพดหรือมันสำปะหลัง)
- [ ] ผ่านสหกรณ์หรือกลุ่มเกษตรกร 30–50 ราย (เป้าหมายขั้นต่ำสำหรับ pilot) · ได้ความยินยอมแบบกระดาษหรือเสียงตามเอกสาร PDPA
- [ ] **วัดก่อน–หลัง:** ราคาที่ขายได้จริง, วันที่ขาย, เวลาที่ใช้ตัดสินใจ, การเข้าใจคำแนะนำ (สัมภาษณ์ 15 นาที)
- [ ] ใช้ความเข้าใจผู้ใช้ 2 แตะ: วัดว่าผู้ใช้ไปถึงคำแนะนำได้ภายใน 2 แตะกี่เปอร์เซ็นต์ (ทดสอบบนมือถือจริง รวม LINE in-app browser)
- [ ] แบบสอบถาม SUS หรือ instrument ที่คล้ายกัน (อธิบายวิธีในเอกสาร)
- [ ] ทุกการใช้งานต้องมี analytics ที่ไม่ระบุตัวตน (มี `api/track.js` และตาราง analytics แล้ว) ตรวจว่าไม่เก็บ PII โดยไม่จำเป็น

**เกณฑ์ผ่าน:** ผู้ใช้ pilot ≥ 30 ราย · ≥ 50% ใช้ซ้ำอย่างน้อย 3 ครั้งในหนึ่งเดือน · ข้อเสนอแนะถูกบันทึกและจัดลำดับ · ไม่มีข้อร้องเรียนด้านข้อมูลส่วนบุคคล

### WP4 · กรอบการวัดผลกระทบ (Logic model) (ควบคู่ WP3)
- **Input:** เงินทุน, ทีม, ข้อมูล, เวลาของเกษตรกร
- **Activity:** เผยแพร่คำแนะนำ, pilot, อบรมสั้น, LINE bot
- **Output (ตัวนับ):** ผู้ใช้ที่ active, คำถามต่อสัปดาห์, รายงานราคาจากเกษตรกร, การตั้งเตือน
- **Outcome ระยะสั้น:** เกษตรกรตัดสินใจขายโดยอ้างอิงข้อมูล, ลดเวลาตัดสินใจ
- **Outcome ระยะกลาง:** ราคาที่ขายได้เปลี่ยนแปลง (เทียบกลุ่มควบคุมถ้าทำได้), ความโปร่งใสของราคาในพื้นที่
- **Impact (SDG 1, 2, 8, 12):** รายได้ของเกษตรกรที่ใช้เครื่องมือ, ของเสียจากการขายผิดจังหวะ (ประเมินด้วยการสัมภาษณ์, อย่าอ้างตัวเลขที่วัดไม่ได้)

> กฎสำคัญ: **ห้ามอ้างผลกระทบที่ยังไม่ได้วัด** ตัวเลข "ขายได้แพงขึ้น X%" ต้องมาจากข้อมูล pilot จริงพร้อมวิธีการเท่านั้น

### WP5 · แพลตฟอร์มและความมั่นคง (สัปดาห์ 2–10, ควบคู่)
- [ ] ตรวจ Supabase RLS ทุก table (ตรวจ `supabase/migrations/` และ schema.sql ให้ตรงกัน) · รันคำสั่ง advisors ของ Supabase
- [ ] ตรวจการรั่วไหลของ key: service-role และ VAPID private ต้องอยู่ฝั่ง server (ตามหลัก README) และยืนยันด้วย grep ใน CI
- [ ] Rate limit บน `api/*` (ผลค้นหาเจอ `limit(100)` แต่ยังไม่มี rate limit ชัดเจน)
- [ ] เลือกและทดสอบการสำรองข้อมูล Supabase และ restore จริงอย่างน้อยหนึ่งครั้ง
- [ ] มอนิเตอร์พื้นฐาน: อัตราข้อผิดพลาดของ API, ความล่าช้า, สถานะ cron, โควต้า LINE
- [ ] บันทึกค่าใช้จ่ายรายเดือนต่อผู้ใช้ 100 / 1,000 / 10,000 คน (Vercel, Supabase, LINE, ข้อความ push)

### WP6 · ความยั่งยืนและแบบจำลองธุรกิจ (สัปดาห์ 12–20)
- [ ] ทางเลือกรายได้ที่ไม่ขายข้อมูลเกษตรกร: เช่น บริการข้อมูลให้สหกรณ์/ผู้ซื้อ (รายงานรวม), ทุนสนับสนุนต่อเนื่อง, การร่วมมือกับหน่วยรัฐ
- [ ] เอกสาร cost per active farmer และจุดคุ้มทุนแบบง่าย
- [ ] แผนรองรับต่อเนื่อง: ใครดูแลข้อมูลหลังสิ้นสุดทุน

### WP7 · ทีมและการกำกับดูแล (สัปดาห์ 1–4)
- [ ] ระบุบทบาท: หัวหน้าโครงการ, นักพัฒนา, ผู้ประสานงานพื้นที่, ที่ปรึกษาเกษตรศาสตร์/เศรษฐศาสตร์, DPO (หรือผู้รับผิดชอบข้อมูล)
- [ ] จดหมายจากสหกรณ์/กลุ่มเกษตรกรที่ตกลงร่วม pilot
- [ ] ผู้ทบทวนอิสระ (external reviewer) ด้านข้อมูลและ PDPA อย่างน้อยหนึ่งคน

### WP8 · ชุดเอกสารยื่นขอทุน (สัปดาห์ 16–24, เริ่มร่างได้ตั้งแต่ต้น)
- [ ] ข้อเสนอโครงการ (proposal) ตามแม่แบบของผู้ให้ทุนแต่ละราย
- [ ] Logic model และ risk register (ข้อ 9)
- [ ] งบประมาณละเอียด (ข้อ 7)
- [ ] แผนงานรายไตรมาส (ข้อ 8)
- [ ] ตัวชี้วัด (ข้อ 10) พร้อม baseline
- [ ] จดหมายสนับสนุนและ MOU
- [ ] ไฟล์ประกอบ: one-pager, pitch deck (ใช้ skill `officecli-pitch-deck` ได้), demo video 2 นาที, ตัวอย่างหน้าจอ, รายงาน pilot ย่อ
- [ ] Data management plan (DMP): แหล่งข้อมูล, การเก็บ, การเผยแพร่, การลบ
- [ ] Ethics/PDPA statement

## 7. กรอบงบประมาณ (ประมาณการ, ปรับตามเพดานทุนจริง)

โครงสร้างหมวด (ใช้สัดส่วนเป็นจุดเริ่มต้น ตัวเลขบาทต้องกรอกจากราคาจริงของทีม):

| หมวด | สัดส่วนโดยประมาณ | รายการหลัก |
|---|---|---|
| บุคลากร | 40–50% | หัวหน้าโครงการ, นักพัฒนา, ผู้ประสานงานพื้นที่, นักวิเคราะห์ข้อมูล |
| การเก็บข้อมูลภาคสนาม | 15–20% | เดินทาง, ค่าอบรม, ค่าตอบแทนผู้ให้สัมภาษณ์, วัสดุ |
| โครงสร้างพื้นฐานและบริการคลาวด์ | 5–10% | Vercel, Supabase, LINE OA, โดเมน, ค่า push |
| ข้อมูลและความร่วมมือ | 5% | ค่าเข้าถึงข้อมูล (ถ้ามี), การตรวจสอบข้อมูล |
| การตรวจสอบอิสระและ PDPA | 5–10% | ผู้ทบทวนภายนอก, ที่ปรึกษากฎหมาย |
| เผยแพร่และชุมชน | 5% | อบรม, เอกสารภาษาไทย, วิดีโอ |
| ค่าบริหารโครงการ (overhead) | ตามเพดานผู้ให้ทุน | — |

> ตรวจสอบ: ผู้ให้ทุนหลายรายมีข้อจำกัดเรื่องอุปกรณ์และ overhead ต้องอ่านกฎของแต่ละรายก่อน
